# 工作台、页库与套版

工作台放在用户指定的工作目录；没有时在当前项目建 `PPT-Rebuild-Workbench/`。
模板可放同一工作台，或由用户指定跨项目共用库。不要擅自遍历其他项目找私有 PPT。

```text
PPT-Rebuild-Workbench/
  inbox/<任务ID>/           投递原始 PPTX、PDF、截图、长图、新内容和标志
  work/<任务ID>/            PAGE-PLAN、拆页、测量、CONTENT-SPEC、BRAND-MAP、IMAGE-SOURCES、预览与成稿
  library/catalog.json       唯一的模板索引，按套编组，按页筛选
  library/<模板ID>/           可编辑模板 PPTX、逐页预览、复用说明
  examples/                 验收用实例、重跑提示词
```

没有索引时先写 `{"schema_version": 1, "decks": []}`。源仍留在 inbox；修改只发生在 work。
现有 PPT、参考图片和历史成稿可迁入：保留原文件，把经过清理和渲染验收的版式登记为模板。

## 怎么复用

1. 列目标页序和每页的任务，例如 交代问题→解释原因→展示方法→呈现效果→总结。
   从同一套模板挑结构连贯的页，按需跨套；单页候选需检查比例、配色、信息密度、字体及邻页连贯性。
2. 用 `python <skill>/scripts/find_templates.py <library目录> --role 研究背景 --style 科研风`。
   `--role` 可匹配别名，不传则遍历可复用页；多个 `--style` 要同时满足。查看对应预览和页说明，
   索引或候选页找不到不代表可以用 HTML：先核对合适的其他参考和主技能规则。
3. 复制库中的原生页/版式到项目副本，用该页的论证、尺寸和图片位置新填内容。注意跨 PPTX 复制应带图片、字体主题、
   组、母版/版式关系等，适合时直接在源模板副本中保留指定页。重新渲染，检查是否意外恢复旧标或残留旧项目内容。
   永远不在库原件上直接替换新项目的内容。

## 怎么入库

- 一套一个稳定 ID，记录标题、版本（更新保留原 ID 并递增版本）、适用场景、比例和整套标签。
  `pages` 按可编辑模板里的实际页序排列；可只收验收通过的页，也可以记录 candidate 供后续测量，检索器不返回 candidate。
- 为每一页分配稳定 ID、原生 PPTX 内从 1 起的页码、一个主用途、可搜索别名、页级风格标签、预览、复用说明、
  文图论证关系和状态。用途例：封面、目录、研究背景、痛点、原因分析、方法路线、原理图、效果展示、对比、案例、
  验证、总结。风格例：科研风、汇报风、简约风、复杂风、答辩风；按实际视觉选，可多选。
- 页说明附源参考位置、文本分工/行数/容量、图片槽的裁法/比例、品牌坐标、来源和复用限制。通用模板中的项目数据、
  商标、署名等用可辨识的示例或占位语，并保留合法的素材署名。没有原生可编辑文件和实际渲染预览的页不能标 verified。
- 对照库中已存在的同构页，能更新既有模板就不重复登记；新的结构或变体才增建。归档时同时更新 JSON，检查路径确实存在。

```json
{
  "schema_version": 1,
  "decks": [
    {
      "id": "research-demo",
      "title": "研究汇报样式",
      "version": 1,
      "ratio": "16:9",

      "pptx": "research-demo/template.pptx",
      "pages": [
        {
          "id": "research-demo-background",

          "role": "研究背景",

          "logic": "痛点总述 → 进展时间线 → 应用约束"
        }
      ]
    }
  ]
}
```
